# jz-create-test-plan

## 目标

生成一份面向 QA agent 的测试意图文档，并自动保存到 gstack 当前项目的 artifact 目录。这个 skill 只写测试计划文件，不实现功能、不修改测试代码、不替代人工发布判断。

默认输出路径必须能被 gstack `/qa` 和 `/qa-only` 自动发现：

```text
{state_root}/projects/{slug}/{branch}-test-plan-{datetime}.md
```

其中 `{state_root}` 通常是 gstack 状态根目录，`{slug}` 是当前仓库的 gstack 项目标识，`{branch}` 是当前 Git 分支，`{datetime}` 是生成时间戳。

## 输入优先级

按以下顺序收集上下文。只读取完成任务所需的信息，避免展开无关文件。

1. 用户显式提供的 PRD、issue、design doc、spec、验收标准、截图说明或功能描述。
2. 当前对话里已经讨论出的产品意图、约束、风险和待验证点。
3. 当前项目中已有的 gstack artifacts，例如 `projects/{slug}` 下的 design、spec、review 或 test-plan 文件。
4. 当前分支的 Git 状态、diff、提交记录、变更文件列表和 TODO 信息。
5. 代码库中与变更相关的 README、CLAUDE/AGENTS 指令、路由、页面、API、测试配置和核心业务模块。

如果没有 PRD、issue 或明确需求，不要直接失败。先从当前对话、分支 diff、文件名、代码行为和已有 artifacts 反推测试意图。只有在无法判断“要测什么”时，才问 3 到 5 个聚焦问题。

## 分析要求

把自然语言需求或代码变更转换成可执行的测试设计。至少覆盖：

- 需求摘要：这次要交付的用户可观察结果是什么。
- 隐含假设：产品、数据、权限、状态、环境、兼容性上的默认前提。
- 业务约束：金额、数量、角色、状态机、频率、地域、时间窗口等规则。
- 边界条件：等价类、边界值、空值、极值、重复、乱序、跨天和跨步骤情况。
- 高风险场景：历史易错点、数据迁移、并发、网络失败、缓存、鉴权、支付、外部服务依赖。
- 受影响页面/路由/API：QA 应该从哪里进入和观察结果。
- 关键交互：用户要点击、输入、上传、提交、撤销、刷新、返回或切换的动作。
- 异常与注入：失败响应、超时、延迟、权限不足、资源不存在、冲突和重试。
- 验证清单：适合人工或 agent 逐项执行的检查点。
- 不在范围内：本轮不需要验证或证据不足的部分。
- 开放问题：会影响测试设计或发布判断的问题。

## 输出格式

写入 Markdown 文件，保留下面这些标题。`/qa` 不要求严格 schema，但会优先读取 `*-test-plan-*.md`，这些标题能让下游 agent 稳定提取测试重点。

```markdown
# Test Plan

Generated by /create-test-plan on {date}
Branch: {branch}
Repo: {repo}
Source: {conversation | spec | issue | design | diff | mixed}
Output template: {template}

## Requirement Summary

## Hidden Assumptions

## Business Constraints

## Boundary Cases

## Risk Scenarios

## Affected Pages/Routes

## Key Interactions to Verify

## Edge Cases

## Critical Paths

## Verification Checklist

## Out of Scope

## Open Questions
```

内容可以用中文写，技术标识、路径、路由、命令和状态字段保留原文。不要复制密钥、token、真实账号、私有域名或内部部署细节；如来源中出现敏感信息，写成 `[redacted]` 并只保留测试判断所需的抽象描述。

## 保存路径

按以下优先级解析输出模板：

1. 用户显式指定的输出路径或模板，例如“输出到 ...”。
2. 环境变量 `JZ_TEST_INTENT_OUTPUT_TEMPLATE`。
3. 本机配置 `~/.config/skills/jz-create-test-plan/config.yml` 中的 `output_template`。
4. 默认模板 `{state_root}/projects/{slug}/{branch}-test-plan-{datetime}.md`。

模板支持这些占位符：

- `{state_root}`：gstack 状态根目录。
- `{slug}`：当前项目 slug。
- `{branch}`：当前 Git 分支。
- `{datetime}`：`YYYYMMDD-HHMMSS` 时间戳。
- `{user}`：当前系统用户名。

除非用户明确要求其它文件名，最终文件名必须包含 `test-plan`。如果用户指定的路径不包含 `test-plan`，仍按用户要求保存，但在回复中说明 `/qa` 和 `/qa-only` 可能不会自动发现该文件。

## 路径解析命令

在当前项目根目录运行下面的解析逻辑，得到输出路径。优先复用本机 gstack helper；如果 helper 不存在，使用保守 fallback。

```bash
GSTACK_SKILL_ROOT=""
for d in "$HOME/.claude/skills/gstack" "$HOME/.agents/skills/gstack" "$HOME/.codex/skills/gstack"; do
  if [ -d "$d" ]; then
    GSTACK_SKILL_ROOT="$d"
    break
  fi
done

if [ -n "$GSTACK_SKILL_ROOT" ] && [ -x "$GSTACK_SKILL_ROOT/bin/gstack-paths" ]; then
  eval "$("$GSTACK_SKILL_ROOT/bin/gstack-paths" 2>/dev/null)"
else
  GSTACK_STATE_ROOT="${GSTACK_HOME:-$HOME/.gstack}"
fi

if [ -n "$GSTACK_SKILL_ROOT" ] && [ -x "$GSTACK_SKILL_ROOT/bin/gstack-slug" ]; then
  eval "$("$GSTACK_SKILL_ROOT/bin/gstack-slug" 2>/dev/null)"
else
  SLUG=$(git remote get-url origin 2>/dev/null | sed 's|.*[:/]\([^/]*/[^/]*\)\.git$|\1|;s|.*[:/]\([^/]*/[^/]*\)$|\1|' | tr '/' '-' | tr -cd 'a-zA-Z0-9._-')
  SLUG="${SLUG:-$(basename "$PWD" | tr -cd 'a-zA-Z0-9._-')}"
  BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null | tr -cd 'a-zA-Z0-9._-')
  BRANCH="${BRANCH:-unknown}"
fi

USER_NAME=$(whoami | tr -cd 'a-zA-Z0-9._-')
DATETIME=$(date +%Y%m%d-%H%M%S)
CONFIG_FILE="$HOME/.config/skills/jz-create-test-plan/config.yml"
CONFIG_TEMPLATE=""
if [ -f "$CONFIG_FILE" ]; then
  CONFIG_TEMPLATE=$(awk '
    /^output_template:/ {
      sub(/^output_template:[[:space:]]*/, "")
      gsub(/^["'\''"]|["'\''"]$/, "")
      print
      exit
    }
  ' "$CONFIG_FILE" 2>/dev/null)
fi

DEFAULT_TEMPLATE='{state_root}/projects/{slug}/{branch}-test-plan-{datetime}.md'
TEMPLATE="${JZ_TEST_INTENT_OUTPUT_TEMPLATE:-${CONFIG_TEMPLATE:-$DEFAULT_TEMPLATE}}"
OUTPUT_PATH="$TEMPLATE"
OUTPUT_PATH="${OUTPUT_PATH//\{state_root\}/$GSTACK_STATE_ROOT}"
OUTPUT_PATH="${OUTPUT_PATH//\{slug\}/$SLUG}"
OUTPUT_PATH="${OUTPUT_PATH//\{branch\}/$BRANCH}"
OUTPUT_PATH="${OUTPUT_PATH//\{datetime\}/$DATETIME}"
OUTPUT_PATH="${OUTPUT_PATH//\{user\}/$USER_NAME}"
mkdir -p "$(dirname "$OUTPUT_PATH")"
printf '%s\n' "$OUTPUT_PATH"
```

## 写入与校验

生成完整 Markdown 后写入 `OUTPUT_PATH`，再重新读取文件确认：

- 文件存在且非空。
- 包含 `# Test Plan`。
- 包含 `## Affected Pages/Routes`。
- 包含 `## Key Interactions to Verify`。
- 包含 `## Edge Cases`。
- 包含 `## Critical Paths`。

最终回复必须给出保存路径，并说明：

- 如果文件名匹配 `*-test-plan-*.md`，gstack `/qa` 和 `/qa-only` 会把它作为当前项目的测试计划候选读取。
- 如果文件名不匹配，只能手动引用该文件或重新保存为匹配命名。
