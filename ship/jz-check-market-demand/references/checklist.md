# 产品市场前景核查表

## 产品定义

- 一句话产品：解决什么问题。
- 目标买家：谁批准预算，谁实际使用。
- 使用场景：什么时候会发生。
- 当前替代方案：表格、人工、外包、已有工具、内部系统。
- 收费方式：订阅、一次性、服务、私有部署、按量。

## 证据分级

强证据：

- 竞品公开收费，且有客户案例、流量、收入、融资或招聘。
- 用户在社区主动求推荐，并描述预算、损失、合规或必须解决的时间点。
- 目标买家愿意接受访谈或试点报价。
- 搜索词包含 `pricing`、`alternative`、`best`、`for <buyer>`、`private deployment` 等购买或场景意图。

中等证据：

- 有不少教程、开源项目和技术讨论。
- 有相关搜索建议，但多为定义、教程、论文。
- 有竞品但定价不清。
- 有痛点讨论，但发言者不一定是买家。

弱证据：

- 只有产品作者或营销页在说需求。
- 只有 GitHub stars，没有真实用户或付费证据。
- 只有趋势词，没有具体场景。
- 只有“这个应该有用”的推断。

## 输出前复查

- 是否说明哪些工具真的跑过，哪些只是看了公开页面。
- 是否把搜索需求、社区讨论、竞品收费、买家触发点分开。
- 是否避免把“技术供给多”误判成“市场需求强”。
- 是否给出可执行的下一步验证，而不是继续加功能。
- 是否附上来源链接。
