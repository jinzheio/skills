# 书籍蒸馏

精读 EPUB 电子书，找出最反大众常识/过往知识的认知，以及最深刻的洞察，输出结构化的 Markdown 读书笔记。

## 工作流

### 第一步：提取文本

使用打包的脚本将 EPUB 转为纯文本：

```bash
python <skill-dir>/scripts/extract_epub.py <epub-path> <output-dir>
```

脚本会将 EPUB 解包，解析所有章节的 HTML，输出一个按章节组织的 .txt 文件到指定目录。

- 输出文件名 = EPUB 文件名（扩展名换成 .txt）
- 脚本会自动跳过目录、版权页、致谢、参考文献等非正文内容
- 确认提取的字数足够（通常应在 10 万词以上）

### 第二步：系统阅读

逐章阅读提取的文本。因为这个文本可能很长（10–15 万词），必须分段读取：

- 先用 Bash 找到章节边界（搜索 `## Chapter block:`）
- 用 Read 工具分段阅读，每次读取一个或两个完整章节
- 边读边在心里记录反常识的观点和深刻的分析框架

阅读时要特别注意两类内容：

1. **反常识认知**：与大众认知、主流医学建议、或作者自己过去的信念相矛盾的事实或研究结论。这些通常有具体的数据支持（风险比、百分比、研究引用）。好的反常识认知读完后让人想说"等等，真的假的？"
2. **深刻洞察**：不是单一事实，而是重新组织问题的分析框架或思维模型。它们解释了"为什么"而非仅仅"是什么"，或者把看似无关的现象统一在一个框架下。好的洞察读完后让人想说"原来如此"。

### 第三步：整理笔记

在读完至少 80% 的章节后，整理出：

- **至少 10 条反常识认知**，按意外程度从高到低排序
- **至少 10 条深刻洞察**，按深刻程度从深到浅排序

每条的具体要求：

- **标题用一句话概括核心观点**（不是描述性标签，是有实质内容的断言）
- **正文 3–6 句展开**，包含书中的关键数据、研究引用或逻辑链条
- **关键术语或颠覆性结论用粗体标出**
- 每条末尾加一个 `**点评/问题：**` 空行，供用户后续填入反馈
- 最终输出不超过 35 条（反常识+洞察），多余的低优先级条目直接舍弃

### 第四步：写出文件

- **输出位置**：从 `~/.config/skills/jz-create-book-notes/config.yml`（或 `.yaml`、`.toml`）中读取 `output_dir`。如果该文件不存在或未指定 `output_dir`，则默认输出到当前工作目录
- **文件命名**：`<书名>.md`（书名从 EPUB 文件名推断，去掉扩展名，转为小写英文短横线连接；中文书名保留原文）
- **文件格式**：

```markdown
# 《书名》反常识与深刻洞察

## 一、最反常识的认知（按意外程度从高到低）

### 1. 一句话核心观点
展开说明，包含数据和逻辑。**关键观点粗体。**

**点评/问题：**

### 2. 一句话核心观点
...

## 二、最深刻的洞察（按深刻程度从高到低）

### 1. 一句话核心观点
展开说明，包含分析框架和逻辑。**关键观点粗体。**

**点评/问题：**

### 2. 一句话核心观点
...
```

- 反常识部分的条目有且仅有一个编号前缀（1. 2. 3. …），不要用"前 10"之类的子标题
- 深刻洞察部分同理

### 第五步：回复点评/问题

用户可能在文件中任意条目末尾的 `**点评/问题：**` 后填入问题。也可能通过对话直接发送问题（如"我的 1.1 问题是：xxx"）。无论哪种方式，按以下规则处理：

1. **先定位再写入**：找到对应的条目，将用户的问题/点评**逐字复制**到 `**点评/问题：**` 行末尾（替换掉原有空白）。如用户已自行写入，则无需重复。

2. **回答问题**：在问题下方新增一段回答，格式为：

```markdown
> **回复：** 回答内容……
```

3. **答案来源**：
   - 优先使用书中内容直接回答（回顾已读的提取文本）
   - 书中确实没有答案时，可以查网络，但回答末尾必须标注 `（来源：外部知识，<URL>）`

4. **追加新的点评/问题行**：在回答段落后追加一个空白的 `**点评/问题：**`，方便用户继续提问，形成讨论记录。

5. **不可修改已有内容**：
   - **绝不修改**任何已有的条目标题、正文、或之前的问题和回答段落
   - 只在文件末尾追加，或在条目的点评/问题区域追加。条目标题编号和主体内容完全不动
   - 这些问答是**讨论记录**，它们是叠加的，不是对原文的编辑

6. **批处理**：如果用户一次提了多条问题，逐一处理；全部答完后报告"共回答 N 条，均在各自的条目末尾"。如果没有任何新问题，直接返回。

## 注意事项

- **不要凭记忆写**：必须实际读完提取的文本。如果你没有逐章读完 80%，不能在笔记中声称已读
- **不要机械搬运章节标题**：反常识和洞察应该来自你对全书内容的综合判断，不是按目录摘抄
- **每一条标题必须有实质信息**：好标题 = "有氧能力差比吸烟更致命"；差标题 = "关于运动的重要发现"
- **精确的数据优于模糊的陈述**：有具体数字的地方优先引用具体数字
- **保持每条独立可读**：读者跳读任意一条都不需要上下文
- **输出文件后告诉用户**：文件路径、总条目数、并提醒可以在各条的"点评/问题："后填入反馈
